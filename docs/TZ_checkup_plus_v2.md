## 3. Канон Чекапа Base и Plus

**Источник:** SoT §1.7.

### 3.1 Принципы

1. **20 вопросов = по 5 на каждый слой** (01 Стратегия / 02 Воронка / 03 Операционка / 04 Деньги).
2. **Гибрид по типу:** для каждого слоя — `3 multiple-choice + 1 numeric + 1 short-text`. Итого: 12 MC + 4 numeric + 4 short-text.
3. **1–2 часа в боте** реально; разбиваем на 4 секции (по слою), между секциями — checkpoint с возможностью паузы.
4. **Pause/resume** обязателен — фаундер не сидит 2 часа подряд. Сохраняем после каждого вопроса (`checkup_current_question_index`, `checkup_last_active_at`).
5. **Принципиально другие вопросы**, чем в Mini. В Mini спрашивали «знаете маржу компании?» (уровень zrelosti), в Чекапе спрашиваем «какая маржа в %?» (цифра).
6. **Skip-логика**: если фаундер пришёл с Mini-Чекапа (`user.quiz_score is not None` и `user.quiz_stage is not None`) — пропускаем повторные стартовые вопросы про сегмент/стадию (это P1/P2 Mini). См. §5.
7. **Качество ответов:** для short-text — min_chars / min_words / expects (как сейчас); для numeric — диапазоны и единицы; для MC — выбор из 5 опций. Дожимы — мягкие (см. §7).

### 3.2 PDF deliverable

**Base (10–12 стр):**
- стр. 1: титул + Score + summary
- стр. 2–3: обзор бизнеса (P1/P2 контекст + что увидели)
- стр. 4–7: 4 слоя по странице (метрики из numeric + диагноз из short-text)
- стр. 8: связи между слоями (3 ключевые связи из канона)
- стр. 9: топ-3 узких места с **agent teaser** (см. §8.3)
- стр. 10: 30-дневный план действий
- стр. 11–12: CTA на Диагностику + контакты + гарантия

**Plus (15 стр):** Base + дополнительно:
- стр. 13: индустриальные benchmarks по сегменту (более детально, чем в Mini)
- стр. 14: «Что внутри Спринта применительно к вам» — 1 страница с привязкой к слабым слоям
- стр. 15: ссылка на 15-мин видео Кати + календарь на разбор

### 3.3 FigJam-карта (упоминается в SoT — но в коде её нет)

**Уровень A (Base):** проблема → причина → симптом × 4 слоя.

**Уровень A+Б (Plus):** A + блок «90 дней действий» с метриками успеха.

> **Важно:** в v2.0 в код мы FigJam **НЕ интегрируем автоматически** (нет Figma API key, времени мало). Делаем ручной шаблон в FigJam, ссылку на скопированный файл выдаём в PDF. Автоматизация — отдельный сабпроект Q3 2026.

### 4.2 Полный текст вопросов

#### Слой 01 · Стратегия

**Q1 (MC) · `c1_strategy_process` · Какой у вас процесс стратегии?**
- 0 — Нет стратегии, плывём
- 3 — Есть «в голове», не записано
- 5 — Записано раз, не пересматриваем
- 8 — Пересматриваем раз в год
- 10 — Квартальный ритм пересмотра стратегии с командой

**Q2 (MC) · `c2_strategy_alternatives` · Как принимаете крупные решения (>3 М ₽ или влияющие на >20% выручки)?**
- 0 — На интуиции, без рассмотрения альтернатив
- 3 — Думаю сам, обсуждаю с парой людей
- 5 — Готовим 2 варианта и выбираем
- 8 — 3+ варианта, сценарный анализ
- 10 — 3+ варианта × финансовый эффект × pre-mortem

**Q3 (MC) · `c3_strategy_review` · Как часто синхронизируете команду по стратегии?**
- 0 — Никогда / неформально
- 3 — Раз в полгода-год
- 5 — Раз в квартал
- 8 — Месячный ритм
- 10 — Месячный ритм + персональные goal-setting раз в квартал

**Q4 (NUMERIC) · `c4_founder_time_strategy_pct` · Какая доля вашего времени уходит на стратегию (не операционку)? %**
- input: integer 0–100
- guidance: «Стратегия = планирование, переговоры по новым направлениям, найм top-tier, инвесторы. Операционка = ежедневные решения, тушение пожаров, контроль сотрудников.»
- expected range: 10–60% (для стадии Команда — норма 25%)
- если 0–5% → красный флаг (фаундер в операционке); 70%+ → проверить, не оторван ли от земли

**Q5 (SHORT-TEXT) · `c5_strategy_antipattern` · Главный анти-паттерн стратегии + механизм отлова (3–5 предложений)**
- min_chars: 120, min_words: 25
- expects: `(один конкретный анти-паттерн, описание механизма отлова, частота проверки)`
- example_good: «Анти-паттерн: соглашаемся на любые проекты от знакомых, размывая фокус. Ловим: правило «новый клиент — только в нашей вертикали или через тендер». Проверка: каждую сделку >2 М ₽ выносим на еженедельный sales-review.»
- why_we_ask: «Анти-паттерн = страховка фокуса. Без неё стратегия размывается тихо.»

### 4.3 Замечания

- Numeric-вопросы — основа PDF (живые цифры). Для них **в боте показываем benchmark по сегменту/стадии прямо в подсказке** после ввода («ваша 21%, средняя по онлайн-школам стадии Команда — 22%»).
- Short-text — это input для PDF и LLM-резюме слоя. Качество — критично.
- MC-вопросы — для быстрого скрининга зрелости + входят в Score Чекапа (см. §6).

### 4.4 Перенесённые вопросы из Mini

При Skip-логике (см. §5) — **пропускаем** Mini-вопросы которые дают то же self-assessment, что и MC Чекапа. Конкретно:

| Mini key | Заменяется в Чекапе на | Логика |

## 6. FSM: pause/resume, 1–2 часа

### 6.1 Состояния (расширение существующего `checkup.py`)

| State | Что ждёт |
|---|---|
| `await_offer_acceptance` | оплата + согласие с офертой |
| `await_pre_p1` (опц.) | сегмент, если нет |
| `await_pre_p2` (опц.) | команда+выручка, если нет |
| `await_intro_confirm` | «Поехали / Расскажи как устроено» |
| `await_q{N}` | где N = 1..20, ждём ответ |
| `await_q{N}_clarify` | дожим качества (см. §7) — до 2 раз |
| `await_section_break` | после каждого слоя — «Продолжим сейчас или сделать перерыв?» |
| `await_final_confirm` | «Всё проверил, готов получить PDF» |
| `generating_pdf` | LLM + WeasyPrint в фоне |
| `done` | PDF + 3 CTA-кнопки |

### 6.2 Pause/resume

- Сохраняем после **каждого** ответа: `applications.checkup_current_question_index = N`, `checkup_last_active_at = NOW()`.
- Если юзер вышел и пришёл через `/checkup`:
  - читаем `checkup_current_question_index` → `«У вас сохранён прогресс: вопрос N/20. Продолжить? [ ✅ Да ] [ Начать заново ]»`
- Через 24 ч молчания на вопросе N — Celery beat task `checkup_remind` шлёт push:
  - 1-й раз: «Вернёмся к Чекапу? Остался вопрос N/20. /checkup»
  - 2-й раз (через 72 ч): «Если передумали — `/refund` оформит возврат за 1 минуту»
  - больше не шлём
- Через 14 дней молчания → проверяем `refund_eligible_until` и если истёк — оставляем applicate в `paid+abandoned` без авторефанда.

### 6.3 Section break (между слоями)

После Q5 / Q10 / Q15 — checkpoint:

```
✅ Слой 01 · Стратегия — готов
   3 minutes на ответы, среднее качество — high

Продолжим сразу или сделать перерыв? Прогресс сохранён.

[ ▶️ Продолжить ]   [ ⏸ Перерыв ]
```

### 6.4 /reset во время чекапа

`/reset` — **только очищает FSM в `context.user_data`, но НЕ удаляет ответы из `checkup_answers`**. При следующем `/checkup` восстанавливаемся на текущем `checkup_current_question_index`.

## 7. Качество ответов и дожимы

### 7.1 Multiple-choice

- Проверка: один из 5 вариантов. Inline-клавиатура. Нет дожима.
- Edge: если юзер прислал текст — «Пожалуйста, выберите один из вариантов кнопкой».

### 7.2 Numeric

- Проверка: парсится в `int`/`float` (`,` → `.`), в диапазоне.
- Если не в диапазоне («200%»): «Похоже, опечатка. Маржа компании обычно 0–60%. Уточните цифру:»
- Если «не знаю»/«не считаю»: `answer_skipped=true`, ставим в PDF плашку «не знает — рекомендуем посчитать в первые 30 дней». **Не блокируем дальше.**
- Если ответ = 0 или подозрительно низкий: мягкий probe: «Маржа 0% — точно? Или имели в виду «не считаю»? [ 0% точно ] [ Не считаю ]»

### 7.3 Short-text

- Существующая логика `core/checkup_questions.py` (`min_chars`, `min_words`, `expects`). Переиспользуем.
- Дожим: до **2 раз** (по 1 итерации). Шаблон уже работает в текущем коде — оставляем.
- После 2 неудачных попыток — принимаем как есть, помечаем `quality_passed=false`. В PDF плашка «ответ требует уточнения на Диагностике».

### 7.4 LLM-роль в чекапе

В v2.0 — LLM **не задаёт уточняющие вопросы свободно**. Дожимы только по правилам (детерминированно). LLM применяется только:
1. На этапе генерации PDF (резюме слоя, рекомендации, agent teaser-блоки).
2. В свободном диалоге `/feedback` или вопросах к боту вне FSM — старая логика `dialog.py`.

**Это намеренно** — детерминированные дожимы предсказуемы, тестируемы и не зависят от Anthropic API uptime.

### 8.6 Генерация

- Сейчас: `tasks/generate_checkup_pdf.py` (Celery task) → пишет файл в `/var/data/checkups/<uuid>.pdf` → ссылку в `applications.checkup_pdf_url`.
- В v2.0:
  1. После Q20 → бот шлёт «PDF готовлю, пришлю в течение 24 часов» (SLA — реально <5 минут).
  2. Celery task: загружает все answers, segment, stage, Mini-context (если был) → строит контекст → LLM генерирует резюме слоя × 4 + 3 agent teaser-врезки → WeasyPrint в PDF.

  4. Параллельно сохраняем backup в S3 (если есть `S3_BUCKET` env) — для исключения потери при пересоздании Railway volume.

### 8.7 LLM-стоимость одного Чекапа

- Резюме слоёв × 4 × ~600 токенов = 2.4 K output
- Agent teasers × 3 × ~250 = 750 output
- Inputs (контекст) ~3 K
- Через `claude-haiku-4-5`: ~$0.005 input + $0.003 output ≈ 0.5 ₽
- + WeasyPrint compute: ~2 секунды CPU

**Маржа Base** = 9 000 − (~1.25 K кост): 86% (см. SoT §2.3).

## 10. Plus: видео-разбор от Кати

1. Юзер выбрал Plus (14 000 ₽) → оплата → `/checkup` → 20 вопросов → PDF готов → бот шлёт PDF + сообщение:

   - `applications.plus_video_uploaded_at = NOW()`
   - `applications.plus_video_url = ...`
5. Background-task `tasks/notify_plus_video.py` (есть в коде, проверить что подхватывает) → шлёт юзеру:

    expects: tuple[str, ...] | None = None
    example_good: str | None = None

### 11.3 Обработка numeric

В `handlers/checkup.py:handle_text_step`:

```python
if q.answer_type == "numeric":
    raw = text.strip().lower().replace(',', '.')
    if raw in ("не знаю", "хз", "не считаю", "skip"):
        if q.allow_skip:
            save_answer(app_id, q.key, answer_skipped=True)
            advance()
            return
        else:
            reply("Это важно для PDF — попробуйте оценить хотя бы примерно.")
            return
    try:
        value = float(raw)
    except ValueError:
        reply(f"Похоже, опечатка. Ответ должен быть числом в {q.numeric_unit}.")
        return
    if not (q.numeric_min <= value <= q.numeric_max):
        reply(f"Цифра вне обычного диапазона {q.numeric_min}–{q.numeric_max} {q.numeric_unit}. Уточните.")
        return
    save_answer(app_id, q.key, answer_numeric=value)
    # Показать бенчмарк
    if q.benchmark_key:
        mean = lookup_benchmark(q.benchmark_key, user.segment, user.stage)
        reply(f"Ваша {q.numeric_unit}: {value}. Средняя по {SEG_LABEL[user.segment]} стадии {STAGE_LABEL[user.stage]}: {mean}. {compare(value, mean)}")
    advance()
```

## 13. Score Чекапа (отдельный от Mini)

Mini Score — это **зрелость по self-assessment** (MC).
Чекап Score — это **зрелость + цифры + качество объяснений** (MC + numeric + short-text quality).

### 13.1 Формула

```python
def checkup_score(answers, stage) -> dict:
    # MC-баллы: 12 вопросов × 10 баллов max = 120
    mc_raw = sum(a.answer_score for a in answers if a.answer_type == 'mc')
    mc_norm = mc_raw * 100 / 120  # 0..100

    # Numeric: для каждого numeric — Z-score от бенчмарка, маппим в 0..100
    num_norm = sum(numeric_to_score(a) for a in numerics) / 4

    # Short-text quality: для каждого — 100 если quality_passed, else 50
    txt_norm = sum(100 if a.quality_passed else 50 for a in shorts) / 4

    # Композит с весами:
    composite = mc_norm * 0.5 + num_norm * 0.35 + txt_norm * 0.15

    # Stage-weighted (как в Mini, веса по слою)
    weighted = apply_stage_weights(composite_by_layer, stage)
    return int(round(weighted))
```

### 13.2 Связь с Mini Score

- Если Mini Score был 67, а Чекап Score 54 — это нормально: на цифрах планка выше.
- В PDF отдельно показываем оба, с пояснением:

  > «Mini-Чекап: 67/100 (по вашей оценке)
  > Бизнес-чекап: 54/100 (с учётом цифр и качества описания узких мест)
  > Δ −13 — типовой gap «как видится» vs «как считается». В Диагностике закроется ещё точнее — на реальных данных из 1С/CRM.»

### 13.3 Категории Score (для PDF копирайта)

Идентичны Mini (см. TZ_mini_checkup_v2.md §5.4).
