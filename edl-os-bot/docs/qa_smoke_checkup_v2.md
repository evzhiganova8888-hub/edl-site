# QA Smoke Test · Чекап v2.0

> **Цель:** 10-минутная проверка перед каждым deploy.
> **Кто:** Катя / Иван (или назначенный QA).
> **Среда:** @edl_os_bot прод, через `/grant_demo <свой tg_id>`.
> **Когда падает:** откатываемся, не релизим.

---

## 1. Бот живой (30 сек)

- [ ] `/start` → видим меню за <2 сек.
- [ ] `/health` (через браузер `https://<railway-url>/health`) → `{"status":"ok"}`.

## 2. Чекап Base — happy path (5 мин)

- [ ] `/grant_demo <свой tg_id> base` → видим «Demo application создан, статус paid».
- [ ] `/checkup` → видим intro («Поехали» / «Сначала расскажи как устроено»).
- [ ] Если без Mini в БД → видим P1 (сегмент) + P2 (команда/выручка). Жмём «онлайн-школа» + «10–25 чел».
- [ ] **Q1 (MC):** видим 5 кнопок «Нет стратегии…» / «Есть в голове…» / … Жмём вариант 3 (5 баллов).
- [ ] **Q4 (numeric):** видим вопрос про % времени фаундера. Шлём `30` → видим acknowledgement с бенчмарком.
- [ ] **Q5 (short-text + section break):** шлём длинный ответ ~30 слов → видим «✅ Слой 01 готов · Продолжим/Перерыв». Жмём «Продолжить».
- [ ] **Q6–Q19:** проходим бегло — отвечаем по дефолту, проверяем что разные типы (MC / numeric / short_text) корректно сменяются.
- [ ] **Q20:** короткий short-text про НДС → шлём 5–6 слов → видим «дополнить/оставить». Жмём «Оставить».
- [ ] После Q20 видим «✅ Все 20 вопросов закрыты, PDF в течение 24 часов».
- [ ] **В течение 5 минут** в чат приходит PDF файл. Открываем.
- [ ] PDF содержит: имя/компания, Score, 4 слоя с цветами, **🤖 АНАЛИЗ-АГЕНТ** + **🤖 ПИСЬМО-АГЕНТ** + **🤖 МОНИТОР-АГЕНТ**, **«45 000 ₽»** в CTA на Диагностику.
- [ ] Финальный экран бота: 3 кнопки CTA («📊 Диагностика 45 000 ₽», возможно «🎬 Доплатить до Plus», «💬 Вопрос Ивану»).

## 3. Возврат /refund (2 мин)

- [ ] `/refund` → видим кнопку `[↩️ Получить возврат]`.
- [ ] Клик → видим подтверждение «Заявка на возврат создана».
- [ ] Иван получает алерт в `ADMIN_CHAT_ID` (если настроен).
- [ ] `SELECT status FROM refunds WHERE application_id=...` → `requested`.

## 4. Force-restart legacy (2 мин)

> Если в проде нет paid с legacy-ключами — пропустить.

- [ ] Найти юзера с `s1_horizon`/`f1_*` ответами в `checkup_answers`.
- [ ] `/checkup` от его имени (через demo) → видим «формат обновился, начнём заново».
- [ ] Клик «Начать заново» → старые ответы стёрты, intro показан.

## 5. Pause/Resume (1 мин)

- [ ] Прервать чекап на любом вопросе кнопкой `[⏸ Перерыв]`.
- [ ] `/checkup` → видим «Продолжить с вопроса N/20».
- [ ] Клик «Продолжить» → возобновляемся с того же вопроса.

---

## ❌ Если что-то не работает

1. **Откат через Railway**: вкладка Deployments → предыдущий deploy → Redeploy.
2. **Логи в Railway**: вкладка Observability → фильтр `level=ERROR` за последний час.
3. **Sentry** (если настроен `SENTRY_DSN`) — ошибки за последние 30 мин.
4. **Db rollback**: `alembic downgrade -1` (только если миграция повредила схему — обычно НЕ нужно).
5. **Iván**: написать в `ADMIN_CHAT_ID` или вручную.

---

## ✅ Если всё прошло — релиз можно публиковать

- Сохраняем PDF из smoke в `docs/qa_audit_<date>/smoke_pdf.pdf` (для регрессии следующего раза).
- Записываем в `release_checklist.md` дату+время smoke pass.
