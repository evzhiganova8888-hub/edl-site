# UX Patterns · TG-боты для фаундеров среднего бизнеса

> **Цель:** свести в одном месте паттерны, которые работают/не работают на нашей ЦА.
> **ЦА:** фаундеры компаний 1–50 чел, оборот до 200 М ₽, 30–55 лет, мобайл-first.
> **Источники:** проекты с похожей ЦА (B2B SaaS onboarding, edutech, business coaching).
>
> Чеклист проверки этих паттернов — для каждого экрана Чекапа.

---

## 🟢 Что работает (P1 — обязательно проверить)

### 1. **Низкий порог входа, постепенное вовлечение**

Фаундеры скептичны. Не дают «email сразу», но дают «пройти Mini-Чекап». Воронка: free quiz → paid Чекап → Диагностика — это правильный ladder.

**Проверить в Чекапе:**
- [ ] Перед оплатой видна гарантия 14-дневного возврата.
- [ ] `/audit_sample` доступен с любого CTA — даёт «попробовать» без оплаты.
- [ ] Никакой email не запрашивается до момента оплаты (или с явным согласием).

### 2. **Прогресс-индикатор — обязателен**

Без прогресс-бара ≥30% юзеров отваливается на «не вижу когда конец».

**Проверить:**
- [ ] Каждое сообщение Чекапа содержит `Вопрос N/20 · ██████░░░░ XX%`.
- [ ] Section breaks показывают «✅ Слой N готов» — даёт ощущение прогресса.

### 3. **«Почему я отвечаю на этот вопрос?» — снимает скепсис**

ЦА — фаундеры, любящие понимать «зачем». Если просто 20 вопросов «вы знаете маржу?» — это анкета. Если «зачем мы спрашиваем + что вы получите» — это диагностика.

**Проверить:**
- [ ] У каждого вопроса есть `why_we_ask` (короткое 1–2 предложения объяснение).
- [ ] Текст не патерналистский («важно для нас») — а конкретный («без этого не покажем benchmark по сегменту»).

### 4. **Pause/Resume — критичен**

1–2 часа подряд фаундер сидеть не будет. Если не сохраним прогресс — теряем 50% completion.

**Проверить:**
- [ ] `[⏸ Перерыв]` доступен на каждом вопросе.
- [ ] После 24+ часов перерыва `/checkup` корректно возобновляет.
- [ ] Section break после Q5/Q10/Q15 — естественная точка остановки.

### 5. **Escape hatch на каждом экране**

ЦА не любит чувствовать себя «запертой» в боте. На каждом экране должна быть кнопка «выйти к человеку» (Иван) или «в меню».

**Проверить:**
- [ ] `[💬 Написать Ивану]` присутствует в финальном экране + при отказе/паузе.
- [ ] `[← В меню]` доступен после pause.
- [ ] Команда `/help` показывает все команды.

### 6. **Авторитетные сигналы**

Фаундер хочет видеть «кто за продуктом». Анонимный бот = недоверие.

**Проверить:**
- [ ] В intro Чекапа упомянуты Катя + Иван.
- [ ] В PDF подвал: «EDL OS · ИП Жиганова Е.В.»
- [ ] Ссылка на оферту явная (не «согласен» в мелком шрифте).

### 7. **Мобайл-first форматирование**

70%+ юзеров читают с телефона. Длинные сообщения и широкие таблицы плохо.

**Проверить:**
- [ ] Сообщения ≤4096 символов (Telegram limit) — реально лучше ≤2500.
- [ ] Inline кнопки full-width, не более 1–2 в ряд.
- [ ] Эмодзи как маркеры (📍📈⚙️💰), не декорация.

### 8. **Деньги — явно и без сюрпризов**

При покупке + при возврате — всё должно быть однозначно.

**Проверить:**
- [ ] Цена 9 000 ₽ / 14 000 ₽ упомянута до клика «оплатить».
- [ ] Ссылка на оферту видна перед оплатой.
- [ ] Условия возврата озвучены 1 раз ясно (не зарытые в FAQ).

### 9. **Анти-spam после взаимодействия**

ЦА жёстко негативно реагирует на push-уведомления без явного консента.

**Проверить:**
- [ ] После Чекапа бот НЕ шлёт «маркетинговые» сообщения без `consent_marketing`.
- [ ] Plus video — это deliverable (обещанный, не реклама), это норм.
- [ ] Pending payment reminder (если включён) — 1 раз через 24ч, без повторов.

## 🔴 Что НЕ работает (P0 — обязательно избежать)

### 1. **«Расскажите про себя в 5 параграфах»**

Фаундер не будет писать сочинение. Короткие short-text (3–5 предложений с явными требованиями) — потолок.

**Проверить:**
- [ ] Short-text вопросы (`c5`, `c10`, `c15`, `c20`) ожидают `min_words=20–30`, не больше.
- [ ] Если ответ короткий — показываем «example_good» как образец, не «напиши больше».

### 2. **Скрытая логика «у вас 12 из 20 failed → возврат отменён»**

Может звучать в оферте, но в боте — НИКОГДА. Юзер не должен думать «я плохо ответил → возврат не дадут».

**Проверить:**
- [ ] Текст возврата: «**безусловный** возврат в течение 14 дней» (соответствует §6.1 оферты).
- [ ] Никаких условий типа «если внедрили рекомендации» в боте.

### 3. **AI-первый язык**

«Наша нейросеть проанализировала ваши ответы» — отпугивает. Лучше: «Катя проанализировала ваши ответы».

**Проверить:**
- [ ] Все упоминания «AI», «нейросеть», «алгоритм» в user-facing текстах заменены на «методология», «Катя», «команда EDL».
- [ ] Только под-капотный комментарий «выпускной экзамен LLM Haiku 4.5» — допустим для тех-аудитории, но НЕ в Чекап-flow.

### 4. **«Ожидайте 24 часа без объяснений»**

Юзер оплатил → ничего не происходит → пишет в саппорт → негативно.

**Проверить:**
- [ ] После Q20: «PDF в течение 24 часов» **И** «обычно за 5 минут».
- [ ] PDF приходит реально за <10 минут.
- [ ] Если задержка >2 часов — алерт админу автоматически.

### 5. **Двусмысленность кнопок**

Кнопка «Назад» в финальном экране может вернуть к Q1 (потеря всех ответов) или в меню. Нужно однозначно.

**Проверить:**
- [ ] Все кнопки имеют чёткие лейблы: `[← В меню]`, `[⏸ Перерыв]`, `[🔄 Начать заново]`.
- [ ] «Начать заново» имеет confirm-step (или нет — если данные не теряем).

### 6. **Confusing «вы ответили хорошо/плохо»**

`quality_passed=false` не должен звучать как «вы плохо ответили». Это про длину/конкретику, не оценку юзера.

**Проверить:**
- [ ] Текст: «Чуть глубже бы, чтобы PDF получился полезным» — рекомендация, не суждение.
- [ ] Никакого «ваш ответ не прошёл проверку» в финальном PDF — там «требует уточнения на Диагностике».

### 7. **Эмодзи перебор**

В русскоязычной B2B-аудитории эмодзи в каждой фразе = «инфоцыган». 1 на экран — норма.

**Проверить:**
- [ ] В каждом сообщении ≤2 эмодзи (маркер слоя + статус).
- [ ] Никаких 🚀🔥💎 в Чекапе.

### 8. **Скрытые ограничения**

«Сделаем за 24 часа», но в footer мелким шрифтом «может занять до 5 дней». Лучше явные SLA.

**Проверить:**
- [ ] SLA в боте = SLA в оферте.
- [ ] Если не успеваем — proactive уведомление, не молчание.

## 🟡 Spec для виральности (бонус)

ЦА — фаундеры — состоят в чатах с другими фаундерами. Если PDF / результат красивый и полезный — будут шарить.

**Что должно быть в PDF чтобы его шарить:**
- [ ] Красивая обложка: имя компании, дата, Score (большая цифра).
- [ ] Уникальные insights для сегмента — «вот что мы видим только у IT-агентств».
- [ ] Один-два «AHA-момента» — neожиданные benchmarks, факт о НДС-2026.
- [ ] Скриншот-friendly секции: одна страница = один insight.
- [ ] НЕТ PD клиента на первой странице — чтобы можно было шарить.

**Виральный hook для NPS:**
- В финальном сообщении бота: «Если Чекап оказался полезным — расскажите коллеге-фаундеру. Бот сохраняет личность.»

## Шаблон для review каждого экрана

Перед мержем нового экрана Чекапа — проверить 10 пунктов:

1. [ ] Прогресс-бар виден.
2. [ ] Кнопка «выйти» или «в меню» есть.
3. [ ] Кнопка «к Ивану» есть (если экран critical).
4. [ ] Текст на «вы», без аббревиатур (CAC/LTV).
5. [ ] Эмодзи ≤2.
6. [ ] Сообщение ≤2500 символов.
7. [ ] Кнопки full-width, не >2 в ряд.
8. [ ] Нет упоминания «AI / нейросеть» (если только не для тех-аудитории).
9. [ ] Если просит данные — есть consent / явное согласие.
10. [ ] Если обещает SLA — соответствует оферте.
